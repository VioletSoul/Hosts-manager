Интерактивная утилита для терминала, которая помогает управлять файлом `/etc/hosts` на macOS. Написана на Zsh.

Проект вдохновлён приложением iHosts. Скрипт ��обирает основные операции с hosts-файлом в простом меню: просмотр, бэкапы, восстановление, добавление и удаление записей, проверка синтаксиса, импорт, экспорт и управление правами доступа.

Дополнительные пакеты и графические приложения не нужны.

## Возможности

- Выбор языка при запуске: English или Русский.
- Цветное интерактивное меню.
- Выход из программы доступен на любом экране: пункт `0` или Ctrl-D.
- Просмотр текущего содержимого hosts.
- Сброс к стандартному шаблону macOS.
- Бэкапы с автоматической ротацией.
- Восстановление из выбранной копии по номеру.
- Автоматический бэкап перед каждым изменением файла.
- Добавление записей IP → имя хоста.
- Удаление записей с предпросмотром и подтверждением.
- Базовая проверка синтаксиса.
- Поиск повторяющихся пар IP–хост.
- Экспорт и импорт файла.
- Просмотр прав, ACL и флагов файла.
- Добавление и снятие явной ACL на запись для текущего пользователя.
- Сброс DNS-кэша после изменений.
- Журнал операций в домашней папке.
- Защита от одновременного запуска нескольких экземпляров скрипта.

## Требования

- macOS.
- Zsh (на современных версиях macOS он стоит по умолчанию).
- Пользователь с правами `sudo`.
- Стандартные утилиты командной строки macOS.

Скрипт использует особенности Zsh и **не совместим с Bash**.

## Запуск

Сохраните скрипт как `hosts_manager_bilingual.zsh` и выполните:

```sh
chmod +x hosts_manager_bilingual.zsh
./hosts_manager_bilingual.zsh
```

Либо так:

```sh
zsh hosts_manager_bilingual.zsh
```

Не запускайте весь скрипт через `sudo`:

```sh
# Так делать не нужно:
sudo ./hosts_manager_bilingual.zsh
```

Скрипт сам запрашивает права администратора там, где они нужны, и отказывается работать от имени root.

## Первый экран

При запуске появляется выбор языка:

```text
Select language / Выберите язык:
  1) English
  2) Русский
  0) Exit / Выход
```

После выбора язык применяется ко всему интерфейсу: меню, подсказкам, подтверждениям и сообщениям об операциях. Пункт `0` закрывает программу ещё до проверок и запроса `sudo`.

Диагностические сообщения самих системных команд, например `sudo` или `cp`, могут оставаться на языке системы.

## Меню

| Пункт | Действие |
| --- | --- |
| `1` | Сбросить hosts к стандартному шаблону |
| `2` | Восстановить из выбранной резервной копии |
| `3` | Показать текущее содержимое |
| `4` | Создать бэкап |
| `5` | Добавить запись |
| `6` | Удалить совпадающие строки |
| `7` | Проверить базовый синтаксис |
| `8` | Найти повторяющиеся пары IP–хост |
| `9` | Экспортировать файл |
| `10` | Импортировать файл |
| `11` | Посмотреть права, ACL и флаги |
| `12` | Добавить ACL на запись для текущего пользователя |
| `13` | Убрать эту ACL |
| `0` | Выход |

После каждого действия скрипт просит нажать Enter и перерисовывает меню.

## Основные операции

### Добавление записи

Выберите пункт `5` и введите IP-адрес и имя хоста:

```text
IP-адрес: 127.0.0.1
Имя хоста: app.local
```

Скрипт проверяет формат, ищет такую же запись, делает бэкап и дописывает строку в конец файла. Если файл не заканчивался переводом строки, запись не склеится с последней строкой.

### Удаление записей

Выберите пункт `6` и введите IP-адрес или имя хоста.

Сравнение идёт по точному совпадению поля, без регулярных выражений. Перед удалением скрипт показывает найденные строки и просит подтверждение.

> Удаляется строка целиком. Если на ней несколько имён хостов, пропадут все привязки с этой строки.

Строки с `localhost` и `broadcasthost` защищены от удаления этой командой. Закомментированные строки не удаляются: они не считаются записями.

### Восстановление из бэкапа

Пункт `2` показывает список копий. Номер `1` — самая свежая:

```text
  1) hosts.backup.20261125221004.aB3dE9xZ
  2) hosts.backup.20261125214512.Qw8rT2yU
```

Введите номер или нажмите Enter для отмены. Перед записью текущий файл тоже сохраняется в бэкап, поэтому восстановление можно откатить.

Выбранная копия сначала читается во временный файл. Благодаря этому ротация, запускаемая при создании нового бэкапа, не может удалить то, из чего вы восстанавливаетесь.

### Сброс

Пункт `1` заменяет содержимое hosts стандартным шаблоном:

```text
## Host Database
# localhost is used to configure the loopback interface
# when the system is booting.  Do not change this entry.
##
127.0.0.1       localhost
255.255.255.255 broadcasthost
::1             localhost
```

Перед заменой делается бэкап.

### Импорт и экспорт

Пункт `9` копирует текущий hosts в указанный файл. Если файл уже существует, скрипт спросит разрешение на перезапись. Экспорт в каталог, символьную ссылку или сам hosts-файл не выполняется.

Пункт `10` заменяет hosts содержимым выбранного файла. Файл должен существовать, быть читаемым и непустым, а перед записью он проходит базовую проверку синтаксиса.

Путь можно вводить с пробелами. Начальный `~` раскрывается в домашнюю папку.

## Настройка

Переменные находятся в начале скрипта:

| Переменная | Значение по умолчанию | Назначение |
| --- | --- | --- |
| `HOSTS_FILE` | `/etc/hosts` | Управляемый файл |
| `BACKUP_DIR` | `/etc/hosts.backups` | Каталог бэкапов |
| `LOG_FILE` | `$HOME/.hosts_manager.log` | Журнал операций |
| `MAX_BACKUPS` | `5` | Сколько копий хранить |

Чтобы изменить значения, отредактируйте эти строки в самом скрипте. Переменные окружения они не читают.

Порог свободного места для бэкапа — 50 МБ — задан прямо в коде.

### Проверка на копии

Чтобы протестировать интерфейс, не трогая системный hosts, измените в скрипте пути:

```zsh
HOSTS_FILE="$HOME/hosts-test/hosts"
BACKUP_DIR="$HOME/hosts-test/backups"
LOG_FILE="$HOME/hosts-test/manager.log"
```

Предварительно создайте каталог и скопируйте туда настоящий файл:

```sh
mkdir -p "$HOME/hosts-test"
cp /etc/hosts "$HOME/hosts-test/hosts"
```

> Это не режим «dry-run». Скрипт всё равно запрашивает `sudo`, выполняет реальные записи в указанные пути и пытается сбросить системный DNS-кэш.

## Бэкапы

Имя копии выглядит так:

```text
hosts.backup.YYYYMMDDHHMMSS.XXXXXXXX
```

Метка времени показывает момент создания, а случайный суффикс гарантирует уникальность: две копии, созданные в одну секунду, не перезапишут друг друга.

Перед каждым изменением файла скрипт создаёт копию и оставляет только `MAX_BACKUPS` самых новых. Новизна определяется временем изменения файла.

Каталог бэкапов принадлежит root, доступ на запись обычным пользователям закрыт.

## Права доступа

Меню прав работает через ACL macOS.

Пункт `12` добавляет явное разрешение на запись для текущего пользователя, пункт `13` убирает именно эту запись ACL.

Это **не** делает файл неизменяемым, не отменяет права, выданные другими способами, и не мешает самому скрипту вносить изменения через `sudo`.

Пункт `11` показывает права вместе с ACL и флагами файла (`ls -leO`). Флаги файловой системы, такие как `uchg`, скрипт не снимает и не ставит.

## Проверка синтаксиса

Базовая проверка находит:

- некорректные IPv4-адреса (в том числе значения октетов больше 255);
- строки без имени хоста;
- адреса, не похожие на допустимые.

Пустые строки и комментарии, включая комментарии в конце строки, пропускаются.

Ограничения:

- Проверка IPv6 упрощённая и не заменяет полноценный разбор по стандартам.
- Имена хостов при проверке файла не валидируются по правилам DNS. Строгая проверка имени есть только при добавлении записи.
- Поиск дубликатов сравнивает текст пары «IP + имя»: разные записи одного IPv6-адреса или разный регистр имён не нормализуются.
- Скрипт не проверяет, что в файле присутствуют стандартные записи `localhost`.

Файлы из ненадёжных источников лучше просматривать перед импортом.

## Как применяются изменения

Для любой операции, меняющей содержимое, скрипт:

1. Готовит новое содержимое во временном файле.
2. Проверяет базовый синтаксис.
3. Убеждается, что файл не пустой.
4. Создаёт бэкап текущего hosts.
5. Копирует новое содержимое в hosts.
6. Сбрасывает DNS-кэш.

Запись происходит на месте командой `cp`, без замены файла через временный файл и `mv`. Так сохраняются владелец, права и ACL, а `/etc/hosts` остаётся символьной ссылкой, какой он и должен быть на macOS.

> Запись не атомарна. Если процесс прервать в момент копирования, файл может остаться записанным частично. Для отката есть бэкап, но риск полностью не исключён.

Если сбросить DNS-кэш не удалось, скрипт предупредит об этом, а сам файл уже будет сохранён. Часть приложений дополнительно кэширует DNS у себя, поэтому в них новые записи могут заработать только после перезапуска.

## Блокировка запуска

Чтобы два экземпляра скрипта не изменяли файл одновременно, создаётся каталог-замок:

```text
/var/run/hosts-manager.lock
```

Замок снимается при нормальном выходе. Если скрипт убит принудительно, например через `kill -9`, замок может остаться. Тогда при следующем запуске вы увидите сообщение о блокировке. Убедитесь, что другой экземпляр не работает, и удалите замок вручную:

```sh
sudo rmdir /var/run/hosts-manager.lock
```

Замок защищает только от одновременного запуска этого скрипта. Другие программы, которые правят hosts, он не блокирует.

## Журнал

Операции записываются в:

```text
~/.hosts_manager.log
```

На экране сообщения цветные, а в файле лежит обычный текст без цветовых кодов. В журнал попадают бэкапы, результаты операций и ошибки, но он не является полным аудитом: вывод всех команд в него не пишется.

## Решение проблем

### Скрипт не запускается от root

Запускайте от обычного пользователя:

```sh
./hosts_manager_bilingual.zsh
```

Права администратора скрипт запросит сам.

### Запись в hosts не удаётся, несмотря на sudo

Посмотрите права и флаги пунктом `11`. Файл может быть защищён флагом файловой системы или другим ограничением, которое скрипт сам не снимает.

### Импорт отклонён

Откройте файл и проверьте строки, на которые указал скрипт: возможно, в них неверный IP или не хватает имени хоста. Базовая проверка не заменяет внимательного просмотра файла.

### Новая запись не работает в приложении

Проверьте пунктом `3`, что запись действительно записана. Затем перезапустите приложение: некоторые программы и браузеры держат собственный DNS-кэш.

### Скрипт сообщает о блокировке

См. раздел «Блокировка запуска» выше.

## Границы проекта

Это локальная административная утилита с интерактивным меню, а не служба и не полная замена графическому менеджеру hosts.

В ней нет:

- атомарной записи;
- полной проверки IPv6 и имён хостов;
- режима «dry-run»;
- включения и отключения отдельных записей, как в iHosts;
- запланированных бэкапов;
- автоматического восстановления после прерванной записи.

## Статус

Личный проект, вдохновлённый iHosts.

Перед использованием просмотрите код и проверьте скрипт на копии файла, прежде чем менять системную конфигурацию.
